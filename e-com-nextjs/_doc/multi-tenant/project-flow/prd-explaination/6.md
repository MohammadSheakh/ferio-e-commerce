# Lesson 6 — Login, Authentication & Authorization in Ferio 🔐

Now we know:

```text
Tenant = business
TenantContext = which business
Tenant DB = that business's data
```

But we have another question:

> **Who is the human making the request, and are they allowed to do it?**

That's what Lesson 6 is about.

---

## 1. Two questions that look similar but are completely different

Imagine someone walks into a bank.

Security asks:

> "Who are you?"

You show your ID.

That's **authentication**.

Then you say:

> "Give me all the money from the bank vault."

😂

Security says:

> "You are Yahya, yes. But you're not allowed to do that."

That's **authorization**.

So memorize:

```text
AUTHENTICATION
      =
Who are you?


AUTHORIZATION
      =
What are you allowed to do?
```

These are different.


# 9. Permission = specific action

Role:

```text
WAREHOUSE_STAFF
```

Permissions:

```text
inventory.read
inventory.update
orders.read
orders.fulfill
```

Think:

```text
ROLE
  =
collection of permissions
```

For example:

```text
ADMIN
 ├── product.create
 ├── product.update
 ├── product.delete
 ├── order.read
 ├── order.update
 ├── customer.read
 └── reports.read
```

So when someone performs an action, Ferio can ask:

```text
Does this user's role have
product.delete?
```

# 12. Now let's talk about JWT

You've asked about JWT before.

JWT stands for:

**JSON Web Token**

Don't focus on the name.

Think of it like a temporary **signed identity card** issued after login.

Rahim logs in:

```text
Email + Password
      ↓
Correct
      ↓
Ferio issues token
```

Conceptually, that token represents information such as:

```text
userId = user_55
```

and other trusted claims appropriate to the authentication design.

Then future requests carry proof of authentication.

```text
Request
   +
authentication token
      ↓
NestJS
      ↓
verify token
      ↓
This is user_55
```

---

# 13. Why not send password every time?

Without a session/token mechanism:

```text
GET products
email + password

POST order
email + password

GET profile
email + password

DELETE product
email + password
```

Terrible idea.

Instead:

```text
LOGIN ONCE

email + password
      ↓
authenticated
      ↓
session/token
```

Then subsequent requests use that authenticated session/token.

---

# 14. JWT is signed

This is important.

Suppose a token says:

```text
userId = user_55
```

A hacker shouldn't simply edit it to:

```text
userId = super_admin
```

and have Ferio accept it.

The server verifies the token's cryptographic signature.

Conceptually:

```text
Token received
     ↓
Signature valid?
   ↙       ↘
 NO        YES
 ↓          ↓
Reject    Continue
```

So JWT is not just random JSON that the browser can safely rewrite.

---

# 15. Access token vs Refresh token

You'll often encounter two concepts:

```text
Access Token
Refresh Token
```

Baby analogy:

### Access token = temporary entrance pass

```text
Valid for relatively short period
```

Used frequently to access APIs.

### Refresh token = mechanism for getting a new entrance pass

When the access token expires:

```text
Access token expired
        ↓
Refresh mechanism
        ↓
New access token
```

This lets access credentials remain relatively short-lived without forcing a full password login constantly.

# 16. Cookies

A browser needs somewhere to maintain session-related information.

One common mechanism is:

```text
Cookie
```

Think of the browser having a small envelope associated with a website.

```text
abc.ferio.com
     │
     └── cookie
```

When the browser contacts the relevant host again, applicable cookies can automatically accompany the request.

# 17. Why host-only cookies matter for Ferio

This is especially interesting in your architecture.

Your checklist says cart/customer/rider session cookies are host-only, meaning the browser naturally keeps them separated by storefront host. 

Conceptually:

```text
abc.ferio.com
     ↓
ABC cookie


perfect.ferio.com
     ↓
Perfect cookie
```

This helps maintain tenant separation at the browser boundary too.

# 26. What is an audit log?

Imagine a CCTV camera for important software actions.

Not literally video.

It records things such as:

```text
Who did it?
What did they do?
When?
Which organization?
What resource?
Why?
```

For example:

```text
10:42 AM
Rahim
ABC Electronics
Deleted Product #123
```

Or:

```text
11:30 AM
Ferio Support Agent
Used support grant
Organization: ABC
Reason: Payment investigation
```

Audit logs are important when someone asks:

> "Who changed this?"

# 27. Authentication failure vs authorization failure

Another useful distinction.

### Authentication failure

```text
Who are you?

I don't know.
```

Typically:

```text
401 Unauthorized
```

Despite the HTTP name, think:

> You haven't successfully authenticated.

### Authorization failure

```text
I know who you are.

But you're not allowed.
```

Typically:

```text
403 Forbidden
```

So:

```text
401
=
WHO ARE YOU? ❌


403
=
I KNOW YOU,
BUT NO. ❌
```

Very useful when debugging APIs.

# 28. Example: deleting ABC product

Let's combine everything.

Rahim sends:

```http
DELETE /products/123
Host: abc.ferio.com
```

Ferio:

```text
1. Resolve hostname
        ↓
   ABC Electronics

2. Create TenantContext
        ↓
   ORG_ABC

3. Verify authentication
        ↓
   user = Rahim

4. Check membership
        ↓
   Rahim ∈ ABC?
        ↓
   YES

5. Check permission
        ↓
   product.delete?
        ↓
   YES

6. Controller
        ↓
   deleteProduct(123)

7. CatalogService
        ↓

8. TenantDbService
        ↓
   current tenant = ABC

9. ABC Prisma Client
        ↓

10. ABC PostgreSQL
        ↓
    Delete ABC product #123
```

Perfect's product #123 is irrelevant.

Even if both databases happen to contain:

```text
Product ID = 123
```

the tenant boundary determines which database is queried.

## The four questions Ferio keeps asking

When you read authentication/authorization code, translate it into these four questions:

```text
1. WHICH BUSINESS?
      ↓
TenantContext

2. WHO ARE YOU?
      ↓
Authentication

3. DO YOU BELONG HERE?
      ↓
Membership

4. CAN YOU DO THIS?
      ↓
Role / Permission
```

If all four answers are correct:

```text
                     ✅
                 CONTINUE
                     │
                     ▼
                  Service
                     │
                     ▼
             Correct Tenant DB
```
